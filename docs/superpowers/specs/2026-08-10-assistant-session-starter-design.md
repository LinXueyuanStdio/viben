# Assistant Session Starter 输入体验设计

## 背景

`apps/web` 的 `/assistant` 空页面目前使用独立的 `SessionStarter`：用户先选择空白会话或仓库会话，再点击创建按钮进入正式对话页。它与正式对话页底部输入框在视觉和操作上割裂，也不能直接输入并发送首条消息。

本次改造把空页面变成 Viben Assistant 欢迎入口。用户可以在欢迎页完成文本输入、模型选择、附件添加和语音转写；发送后系统创建对应 session，进入正式对话页，并自动发送完整首条消息。

## 目标

- 在 `/assistant` 空页面展示 `Viben Assistant` 欢迎 Logo 和居中的大卡片。
- 欢迎页与正式对话页复用同一套输入框 UI，包括文本输入、图片附件、长文本附件、拖放、语音转写、模型选择和发送按钮。
- 在输入框卡片底部增加灰色 session 模式操作行。
- 默认创建空白 chat；用户也可以通过原仓库选择器创建 repo session。
- 创建成功后自动进入正式对话页并发送用户在欢迎页准备的首条消息。
- 任一步骤失败时不静默丢失用户输入或附件。

## 非目标

- 不改造消息协议、流式响应协议或 session 创建 API。
- 不在欢迎页展示尚未产生的上下文用量。
- 不新增服务端“创建 session 并发送首消息”的复合接口。
- 不重构与本次输入框复用无关的正式对话页面结构。

## 用户界面

### 欢迎区

页面主体继续在可用区域内水平、垂直居中。输入卡片上方展示 Viben 品牌标识和 `Viben Assistant` 欢迎标题。整体宽度与正式对话输入区协调，在窄屏上保留页面边距，在宽屏上使用大卡片承载输入体验。

### 共享输入框

抽取受控的共享输入框组件，统一以下界面与基础交互：

- 自动增高的 textarea；
- 图片选择、粘贴和拖放；
- 大段文本转换为文本附件；
- 图片与文本附件预览及移除；
- 模型选择器；
- 语音录制、转写、处理中状态和错误提示；
- 可用、禁用和发送中状态；
- 圆形发送按钮及 Enter 发送行为。

共享组件只负责输入体验，不拥有 session、chat、沙箱或流式响应状态。正式对话页继续向它提供停止生成、上下文用量、内联提问等会话专属能力；欢迎页只提供创建 session 和交接首消息所需的状态。这样两处使用相同的基础 UI，又不会把正式对话运行时耦合进空页面。

### Session 模式操作行

共享输入框卡片底部增加一行灰色背景区域：

- 左侧 Cloud 图标是独立按钮，点击后导航至 `/settings/sandbox`；
- 右侧默认显示 `New chat >`；
- 点击 `New chat >` 后进入仓库 session 选择状态，文案切换为 `New session >`，并打开原有 repo 选择器 popover；
- repo 选择器沿用现有仓库、分支、Vercel 项目和 Git 自动化设置能力；
- popover 关闭时如果用户没有选定仓库，取消本次选择，清理临时 repo 状态并自动恢复 `New chat >`；
- 用户选定仓库后保持 `New session >` 状态，发送时创建 repo session；
- 未进入仓库模式时发送，创建空白 session。

试用用户或 GitHub 状态不允许创建 repo session 时，沿用当前禁用规则，并保持空白 chat 可用。

## 组件边界

### `AssistantPromptComposer`

新增共享展示组件，接收受控输入值、附件集合、模型信息、录音状态、禁用状态和回调。它提供输入框卡片的统一 DOM 结构与样式，并通过可选插槽容纳正式对话页专属的上下文用量、停止按钮或内联提问界面。

### `SessionStarter`

调整为欢迎页编排组件，职责包括：

- 管理空白 chat/repo session 模式；
- 管理 repo popover 的打开、确认和取消；
- 复用图片、文本附件和语音 hooks；
- 加载默认模型和可选模型；
- 组装首消息草稿；
- 请求上层创建 session，并在成功后发起路由跳转。

现有 repo、branch、Vercel 和 Git 设置 UI 保留为 repo popover 内容，不复制其业务逻辑。

### 首消息一次性交接区

新增小型客户端模块，以 `chatId` 为键保存待发送首消息。数据包括：

- 文本；
- 已压缩图片对应的 file parts；
- 文本附件对应的 snippet parts；
- 用户选择的模型 ID。

交接区使用当前客户端运行周期内的一次性内存存储。`router.push` 是同一页面运行周期内的客户端导航，不需要把可能较大的图片 data URL 写入 `sessionStorage`，从而避免浏览器存储配额和序列化副作用。数据通过 `take` 操作原子读取并删除，确保同一草稿不会自动发送两次。

若导航前创建失败，草稿仍保留在 `SessionStarter` 的受控状态中，不写入交接区。若用户在导航过程中主动刷新导致内存交接数据消失，正式页面只显示已创建的空 chat，不尝试发送不完整消息。

### 正式对话页消费逻辑

正式对话运行时就绪后，根据当前 `chatId` 读取一次性交接数据：

1. 把草稿恢复到共享输入状态；
2. 如果草稿模型与新 chat 默认模型不同，先通过现有模型更新逻辑切换模型；
3. 使用现有消息 payload 构造与发送链路提交文本、图片和 snippets；
4. 沿用现有首消息标题生成、沙箱准备、流式状态和错误处理逻辑；
5. 发送成功后清空恢复的输入状态。

语音输入在欢迎页完成转写，交接的是转写文本，不交接原始音频。

## 数据流

```text
欢迎页输入
  -> 共享输入框状态（文本 / 图片 / snippet / 模型）
  -> 用户发送
  -> 创建空白或 repo session
  -> 以 chatId 写入一次性交接区
  -> router.push 正式对话页
  -> 正式运行时 take 草稿
  -> 必要时更新模型
  -> 复用现有发送链路自动发送首消息
```

## 状态与异常处理

- 创建中禁用输入、模型选择、模式切换和发送按钮，防止重复 session。
- session 创建失败时停留在欢迎页，并保留文本、附件、模型及 repo 选择。
- repo popover 未完成选择便关闭时恢复空白 chat 模式。
- 模型列表加载失败时允许使用 session API 返回的新 chat 默认模型，不阻塞文本发送。
- 自动发送失败时，将已取出的草稿恢复到正式输入框，保留附件并允许用户手动重试。
- 自动发送逻辑需要防御 React Strict Mode 重复执行；一次性交接的 `take` 语义和本地处理中标记共同保证只提交一次。
- Cloud 图标只负责导航，不改变当前输入草稿。

## 可访问性与响应式

- Cloud、附件、语音、模型和发送按钮提供可翻译的可访问名称。
- 所有模式切换和 popover 操作支持键盘访问与焦点返回。
- repo popover 关闭后焦点返回模式按钮；取消时更新按钮文案与可访问状态。
- 发送按钮的禁用状态同时覆盖无内容、创建中、录音处理中和模型更新中。
- 使用项目现有语义色彩变量与 Tailwind 类，不用 `hsl()` 包裹 oklch 变量。
- 移动端保持触摸目标尺寸，并沿用正式输入框的 iOS 发送键盘处理。

## 国际化

新增或调整的欢迎语、模式文案、按钮可访问名称和错误提示全部进入 locale JSON。英文使用 `New chat`、`New session`；简体中文遵循项目约定。既有 session starter 翻译键可复用时不重复创建。

## 测试策略

### 单元与组件测试

- 共享输入框渲染文本区、附件、模型、语音和发送控件，并正确触发受控回调；
- 默认显示 `New chat >`，点击后显示 `New session >` 并打开 repo popover；
- 未选择 repo 关闭 popover后恢复 `New chat >`；
- Cloud 图标导航到 `/settings/sandbox`；
- 创建失败时保留完整草稿；
- 创建成功后按 chat ID 写入一次性交接数据；
- `take` 同一草稿两次时第二次返回空，证明不会重复自动发送；
- 正式页面消费草稿时先应用模型，再发送包含文本、图片和 snippets 的 payload；
- 自动发送失败时恢复草稿。

### 验证

- 运行本次新增与相关 assistant 测试；
- 在 `apps/web` 目录运行 `pnpm typecheck`；
- 在 `apps/web` 目录运行 `pnpm build`；
- 手动检查桌面端与移动端的空白 chat、repo session、取消 popover、附件、语音、模型切换和首消息自动发送流程。

## 成功标准

- `/assistant` 空页面展示 Viben Assistant 欢迎标识与大输入卡片；
- 欢迎页和正式对话页的基础输入框来自同一个共享组件；
- 所有要求的输入能力在欢迎页可用；
- Cloud 与 session 模式操作符合指定导航和回退行为；
- 空白 chat 与 repo session 均可携带完整首消息进入正式页面并自动发送；
- 创建或发送失败不会静默丢失草稿；
- `apps/web` 测试、类型检查和构建通过。
