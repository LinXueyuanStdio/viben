2. 后台任务执行流程

sequenceDiagram
    participant U as 用户
    participant FE as Frontend
    participant BE as Backend API
    participant Agent as AI Agent
    participant Tools as 工具执行器
    participant FS as 文件系统

    U->>FE: 输入任务描述
    FE->>BE: POST /agent/plan (SSE)
    BE->>Agent: 创建执行计划
    Agent-->>BE: 流式返回计划
    BE-->>FE: SSE: plan 消息
    FE-->>U: 显示执行计划

    U->>FE: 批准计划
    FE->>BE: POST /agent/execute (SSE)

    loop 任务执行
        BE->>Agent: 执行下一步
        Agent->>Tools: 调用工具
        Tools->>FS: 读/写文件
        FS-->>Tools: 返回结果
        Tools-->>Agent: tool_result
        Agent-->>BE: 流式消息
        BE-->>FE: SSE: text/tool_use/tool_result
        FE-->>U: 实时更新 UI
    end

    BE-->>FE: SSE: done
    FE-->>U: 任务完成

3. 核心 API 端点

Agent API Routes
方法 端点 描述
POST /agent/plan 创建执行计划（阶段一），返回 SSE 流
POST /agent/execute 执行已批准的计划（阶段二），返回 SSE 流
POST /agent/ 直接执行（计划+执行一体化，旧版兼容）
POST /agent/stop/:sessionId 停止正在执行的任务
GET /agent/session/:sessionId 获取会话状态和信息

两阶段执行模式

WorkAny 采用 Plan → Approve → Execute 的两阶段模式，确保用户对 AI 操作有完全控制：

  • Planning Phase: AI 分析任务，生成详细执行计划
  • User Approval: 用户审核计划，可修改或拒绝
  • Execution Phase: 按批准的计划执行，实时反馈进度

// /src/shared/lib/background-tasks.ts class BackgroundTaskManager { private tasks: Map<string, BackgroundTask> = new Map(); private listeners: Set<(tasks: BackgroundTask[]) => void> = new Set(); addTask(task: BackgroundTask) { this.tasks.set(task.id, task); this.notifyListeners(); } updateTaskStatus(id: string, status: TaskStatus) { const task = this.tasks.get(id); if (task) { task.status = status; this.notifyListeners(); if (status === 'completed') { setTimeout(() => this.removeTask(id), 5000); } } } }

9. 关键设计模式

SSE 流式通信

  • 实时推送执行进度到前端
  • 支持消息增量渲染
  • AbortController 实现任务取消

插件化 Agent 架构

  • 统一 IAgent 接口抽象
  • 支持多 Provider 无缝切换
  • MCP 协议扩展工具能力

会话隔离

  • 每个任务独立工作目录
  • Session ID 追踪任务状态
  • 自动清理已完成会话

两阶段执行

  • Plan → Approve → Execute
  • 用户对 AI 操作完全控制
  • 支持计划修改和拒绝
